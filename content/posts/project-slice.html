为什么我想写“项目切片”

很多项目做完之后，公开留下来的往往只有仓库地址和最终截图。 但真正值得回看的，通常是中间那些不够完整、却很有价值的局部思路。

所以我想把项目拆成一块一块更容易阅读的小片段，例如：

  • 某次架构上的取舍
  • 某个难点是怎么被定位出来的
  • 某个界面或模块为什么最后长成这样

这种写法适合放什么

它不一定是完整复盘，也不一定是教程，更像是从项目里抽出一个值得被单独记住的部分。

不是每个项目都要写成长文，但很多项目里都藏着值得保留下来的一个判断。

这篇文章保留为 HTML 内容，是为了验证博客结构可以同时兼容 Markdown 和 HTML 两种写作方式。
